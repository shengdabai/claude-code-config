# Codex 故障排查指南

## 🔍 问题诊断

根据终端错误信息，可能的原因有：

### 1. ⚠️ wire_api 配置缺失（已修复）
**错误信息**: `Support for the "chat" wire API is deprecated`

**解决方案**: 已在所有 model_providers 中添加 `wire_api = "responses"`

### 2. ❌ 模型不存在错误
**错误信息**: `{"error":{"code":"1211","message":"模型不存在，请检查模型代码。"}}`

**可能原因**:
- 模型名称不正确（`glm-4.5` 可能不存在）
- API Key 未设置或无效
- 配置文件未正确复制到 `~/.codex/config.toml`

## 🛠️ 解决步骤

### 步骤 1: 确认配置文件位置

```bash
# 检查配置文件是否存在
ls -la ~/.codex/config.toml

# 如果不存在，复制配置文件
mkdir -p ~/.codex
cp ~/Desktop/编程/Claude\ Code配置/codex/config.toml ~/.codex/
```

### 步骤 2: 检查并设置 API Key

```bash
# 检查智谱 API Key 是否设置
echo $ZHIPUAI_API_KEY

# 如果没有设置，添加到 ~/.zshrc 或 ~/.bash_profile
export ZHIPUAI_API_KEY="你的API密钥"
```

**获取 API Key**:
- 智谱 GLM: https://open.bigmodel.cn/
- Kimi: https://platform.moonshot.cn/
- DeepSeek: https://platform.deepseek.com/

### 步骤 3: 尝试不同的模型名称

如果 `glm-4.5` 不存在，尝试以下模型名称：

```toml
# 选项 1: GLM-4 (标准版)
model = "glm-4"

# 选项 2: GLM-4-Plus (增强版)
model = "glm-4-plus"

# 选项 3: GLM-4-Flash (快速版)
model = "glm-4-flash"

# 选项 4: coding-glm-4 (编程专用)
model = "coding-glm-4"
```

### 步骤 4: 切换到其他模型提供商（临时测试）

如果 GLM 有问题，可以临时切换到 DeepSeek 或 Kimi：

```bash
# 编辑配置文件
code ~/.codex/config.toml

# 修改默认模型
model_provider = "deepseek"
model = "deepseek-chat"  # 或 deepseek-coder
```

然后设置对应的 API Key：
```bash
export DEEPSEEK_API_KEY="你的DeepSeek密钥"
```

### 步骤 5: 验证配置

```bash
# 重新启动终端或重新加载配置
source ~/.zshrc  # 或 source ~/.bash_profile

# 测试 Codex
codex --version

# 启动 Codex
codex
```
